# `period_selection.read`: the period grammar and the stored reading move into the module

From the architecture review of 8 October 2026: period selection becomes one module, per `docs/process/tickets/period-selection/design.md` and ADR 0015. Restructure only: **no behaviour may change**. Read the design record in full before starting; its interface and its behaviour-preservation checklist are the spec.

**Files (this ticket only):** `src/financial_analyst_agent/period_selection.py` (new), `src/financial_analyst_agent/period_window.py` (deleted), `src/financial_analyst_agent/request_wording.py`, `src/financial_analyst_agent/graph/state.py`, `src/financial_analyst_agent/graph/turn_graph.py`, `src/financial_analyst_agent/graph/spec_turn.py`, `src/financial_analyst_agent/rules_planner.py`, `src/financial_analyst_agent/answer_notes.py`, `tests/unit/test_period_window.py` (renamed `test_period_selection.py`), `tests/unit/test_planner_window.py`, `tests/unit/test_derived_and_named_periods.py`, `tests/unit/test_planner_understanding.py`, `tests/unit/test_window_copy.py`, `tests/unit/test_planner_wording.py`, `tests/unit/test_calendars_clarification_and_formatting.py`, `tests/unit/test_filers_rankings_and_narrowing.py`

**What to build:** `period_selection.py` is born with `read(message, *, stored=None) -> Words` and the types it needs, exactly as the design record gives them. This ticket covers the reading and the proposal step; binding (ticket 03), dating (04), grouping (05) and notes (06) follow.

1. **`WindowReading` moves** from `request_wording` into the module, its nine fields unchanged, gaining `year_to_date: bool = Field(default=False, exclude_if=lambda v: not v)`, read from today's `YEAR_TO_DATE` pattern. `graph/state.py` and `answer_notes.py` import it from the module. `CHECKPOINTED_TYPES` is unchanged; a persistence test asserts `WindowReading.model_dump()` is unchanged over a corpus of wordings (every phrase-coverage case is a convenient corpus).
2. **The grammar moves in**: the whole of `period_window.py` (which is then deleted) and the named-period grammar from `request_wording` (`parse_named_periods`, `_full_year`, and the patterns `_YEAR`, `_FISCAL_WORD`, `_CALENDAR_WORD`, `_QUARTER_WORDS`, `_NAMED_PERIOD_PATTERNS`, `_MONTH_QUARTER_PATTERNS`, `_YEAR_RANGE`, `_MAX_RANGE_YEARS`, `_YEARS_AGO`, `_HALF_YEAR`, `SINCE_YEAR`, `_LATEST`, `_PERIOD_CUE`, `SUB_QUARTER`, `SPECIFIC_PERIOD`, `YEAR_TO_DATE`, `YEAR_OF_QUARTERS`, `TRAILING_YEAR`, `INVALID_QUARTER`, `window_words`, `_names_a_window`, `_names_a_span`, `_within`, `read_window`). No pattern's text changes; check each string literal appears verbatim after the move. Which text each pattern reads (raw message or `window_words`) is on the checklist.
3. **`Words`** carries `message`, `reading`, `named` and `names_a_window`. `request_wording.comparison_asked` and `_asks_change` use `read(message).names_a_window` and `.named` where they called `_names_a_window`, `_names_a_span` and `parse_named_periods`; `rules_planner` uses `len(read(normalized).named) >= 2`.
4. **`Words.propose`** replaces `request_wording.planner_window` and the period part of `spec_turn.plan_to_spec_patch` (the cap at `MAX_QUARTERS_ASKED`, none for a rank intent). `turn_graph.request_from_proposal` calls it and stores `words.reading` on the request. The log event names (`planner_window_overruled`, `planner_window_dropped`) are kept.
5. **`spec_turn.resolve_request`** reads `words = read(message, stored=request.window)` once and passes `words` where it passed `request.window` into `refine_patch_from_message` (whose `window=` parameter becomes `words=`; the binding inside it still lives in `request_wording` until ticket 03 and takes `words.reading`).
6. **No re-exports.** Every caller of a moved name imports it from `period_selection`; `request_wording` keeps no alias. Tests of the moved functions are rewritten against `read` and `Words` and the old tests deleted; `test_period_window.py` becomes `test_period_selection.py`.

**Acceptance:** `uv run python -m pytest` passes; ruff and mypy are clean; `uv run python scripts/compare_answers.py --against master` reports `0 of N conversations differ`; phrase coverage stays 555 of 555; the rules planner passes the same planner cases as master, case for case; `period_window.py` no longer exists and no module but `period_selection` defines a period regex. The checklist items touched: never bind at proposal time; which text each regex reads; `year_to_date` uses `exclude_if`; no re-exports. If a step would change behaviour, or needs a file outside this ticket's list, leave it and say so in the Answer.

## Answer

Resolved 8 October 2026. `src/financial_analyst_agent/period_selection.py` is born with `read(message, *, stored=None) -> Words`, `Words` (`message`, `reading`, `named`, `names_a_window`, `propose`) and `WindowReading`; `period_window.py` is deleted. `compare_answers.py --against master` reports `0 of 893 conversations differ`; 2,434 tests pass (32 new); ruff and mypy are clean.

- **`WindowReading`** moved unchanged, plus `year_to_date: bool = Field(default=False, exclude_if=lambda v: not v)`, read from `YEAR_TO_DATE`. `test_the_stored_reading_dumps_as_before_over_every_phrasing` checks every phrase-coverage wording dumps the nine fields alone unless year-to-date words are present, and round-trips.
- **The grammar moved in whole.** A scratch script loaded master's `period_window` and `request_wording` and compared every `re.Pattern` by `.pattern` and `.flags` with its new home: 69 patterns, all verbatim, none missing. Which text each reads is unchanged: `YEAR_OF_QUARTERS`, `YEAR_TO_DATE` and `names_a_window`'s `SINCE_YEAR` search the raw message; the counted window, `SPECIFIC_PERIOD`, `SUB_QUARTER`, `TRAILING_YEAR` and the since-year of the reading search `window_words`; `since_year` is read only when no counted window matched. `parse_named_periods`, `asked_window`, `AskedWindow`, `window_words`, `read_window`, `_within`, `_names_a_window` and `_PERIOD_CUE` are private to the module (`_named_periods`, `_asked_window`, `_AskedWindow`, `_window_words`, `_read_window`); callers go through `read`.
- **Two patterns the ticket's list left out moved too**, because `names_a_window` and the binding need them and the module imports nothing from `request_wording`: `_YEAR_BASE` ("over the past year") is now `period_selection.YEAR_BASE`, and `_LATEST` is `period_selection.LATEST`. Both are public only so `bind_periods_from_message` can import them until ticket 03 moves the binding in. `MAX_SINCE_QUARTERS` stays in `request_wording` with the binding.
- **`Words.propose`** replaces `planner_window` and the window part of `plan_to_spec_patch`: `model_quarters` (the plan's `recent_quarters`, `None` for a `SpecPatch` proposal or a rank intent, decided in `turn_graph.request_from_proposal`) is set, capped at `MAX_QUARTERS_ASKED`, only when at least 1, as before; then the planner-window rule with the same two log events. `plan_to_spec_patch` is now the lifting alone (the old `_lifted_plan`). `test_proposing_never_binds_the_words` pins that a proposal keeps the planner's count.
- **`resolve_request`** reads `words = read(message, stored=request.window)` once and passes `words=` to `refine_patch_from_message`, whose parameter is `words: Words | None = None` (read from the message when a test calls it without one, as `window=None` was). `bind_periods_from_message` keeps `window=` and takes `words.reading`; it reads the named periods through `read(message, stored=window).named`. `_keep_window_for_change` takes `words`. `comparison_asked` uses `read(message).names_a_window`; `_asks_change` is `names_a_window or len(named) <= 1`, the same truth table as `_names_a_window or not _names_a_span`.
- **No re-exports.** `request_wording` imports `LATEST`, `YEAR_BASE`, `WindowReading`, `Words` and `read` for its own use and aliases nothing. `answer_notes` imports `YEAR_OF_QUARTERS`, `YEAR_TO_DATE` and `WindowReading` from the module (its re-search of the message is ticket 06's); `spec_turn` imports `INVALID_QUARTER`; `state`, `clarify`, `rules_planner` and `turn_graph` import `read`.
- **Two files outside the ticket's list changed, by one import each**, because leaving them would have failed the suite and the no-re-export rule: `graph/clarify.py` (`read(wording).reading` for `read_window`, `WindowReading` from the module) and `tests/test_says_what_it_cannot_do.py` (its `date.today` monkeypatch now targets `period_selection`, where `_YEARS_AGO` reads it). `tests/unit/services/test_metric_phrase.py` imports `TRAILING_YEAR` from the module. Recorded in `docs/process/rules-to-review.md`.
- **Tests:** `test_period_window.py` is `test_period_selection.py`, against `read`: the window table, no-window table, approximate and capped notes (as `interpretation_notes`), the named-period table (moved here from `test_derived_and_named_periods`, with half-year, year-range and month-quarter rows), `names_a_window`, `year_to_date`, the persistence test and `stored`. `test_planner_window.py` is against `Words.propose`. The old `read_window`/`parse_named_periods` tests in `test_window_copy`, `test_derived_and_named_periods` and `test_planner_understanding` are rewritten or folded in.
